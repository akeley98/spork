\magicSection{Basic Idea}{sec:BasicIdea}

Managed ring buffer: One non-distributed dimension of the allocation is marked to be ring buffered by an integer \lighttt{ring\_depth}.
This is by extending \lighttt{LoopIR.Size} to have a \lighttt{SizeAnnotation?} member.
The extent of the managed ring-buffer dimension is transparently rewritten to \lighttt{ring\_depth}, and any corresponding indexing expression \lighttt{e} is transparently rewritten to \lighttt{(e + \emph{consumption}) \% ring\_depth}.

\magicSection{Sync Check}{sec:SyncCheck}

Each managed ring buffer alloc \lighttt{x} must be guarded by exactly one \lighttt{z: barrier}, except that managed ring buffer \lighttt{barrier} types \textit{may} be not guarded by another barrier; if so, they are self-guarded barriers.

Define later what multicast group is.
Let \lighttt{d$^*$} be distributed indices, \lighttt{k} the index on the managed ring buffer dimension, and \lighttt{e$^*$} the other indices.
For self-guarded barriers \lighttt{z[d$^*$, k, e$^*$]}, you have to wait for any barrier in the multicast group of \lighttt{z[d$^*$, k-RING, e$^*$]}, unless \lighttt{k < RING}. (This unless is a bit of a blind spot in the checking).
For non-self-guarded managed ring buffer allocations \lighttt{x[d$^*$, k, e$^*$]}, you have to wait for any barrier in the multicast group of \lighttt{z[d$^*$, k, e$^*$]}; truncate $e^*$ if needed.
