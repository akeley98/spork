## Mistakes found

### ExprSemantics.tex
- [x] E-Read's result was bare `r`, not `\sporkr`, so it had no hyperlink. Fixed during the conversion.
- [ ] `\sporkSigma \equiv \sporkV \to \mathbb{N}^* \to \sporkR` (BasicGrammar) is indexed by naturals, but E-Read looks up `\sporksigma(\sporkv, \sporkz^*)` with integers.
  Either use `\mathbb{Z}^*` in Σ or add a bounds/non-negativity side condition to E-Read.
- [ ] There is no congruence rule for `\sporkextern(\sporke^*)` arguments.
  The caption only covers externs whose arguments are already constants (`exp2(3)`), so `exp2(x[0])` gets stuck.
- [ ] Comparison bin-ops `\sporke_L \oplus \sporke_R : \sporkBoolExpr` rely on E-BinOpLhs/Rhs, but those rules are written over `\sporke`.
  It should say explicitly that ⊕ in E-BinOp* also covers comparisons, and that the result can be a `\sporkb`.

### ControlSemantics.tex
- [x] C-AssertStep was written `assert b_1:s`, but the grammar's `assert b` has no body. Removed the `:s`.
- [x] C-AssertPass used `\sporktr` instead of `\sporktr^*`. Fixed.
- [x] Several rules used bare `s`, `v`, `s'` (no hyperlink) instead of `\sporks`/`\sporkv`. Fixed.
- [x] C-IfTrue/C-IfFalse/C-AssertPass used literal `True`/`False` text instead of `\sporkTrue`/`\sporkFalse`. Fixed.
- [ ] There is no C-AssertFail rule, so `assert False` is a stuck state.
  If that is the intended meaning (stuck = UB/error), the caption should say so.
- [ ] In C-ForIter, `\sporkz_\textrm{lo} + 1` appears inside program syntax (`\texttt`).
  It is ambiguous whether this is meta-level addition (already a constant) or an Exo expression that E-BinOp* and constant folding must step.
  It doesn't change the result, but meta-level addition would avoid an extra step.
- [ ] C-ForIter substitutes `\sporkv \mapsto \sporkz_\textrm{lo}` into `\sporks`, but no figure defines substitution (`s[v \mapsto z]`) or `\alpha\textrm{-rename}`.
  Should these get a figure or a forward reference?
- [ ] The grammar gives `with CudaWarps(z, z, name=...)` and `with CudaDeviceFunction(clusterDim=..., warp_config=...)`, but the rules use `(...)`.
  The rules ignore the arguments, which is fine, but `warp_config` presumably constrains `\sporktidMap_\textrm{allThreads}`, and that link isn't stated.
- [ ] `\forall\sporksigma' \in \sporkSigma.\sporktidMap_\textrm{allThreads}(\sporksigma') = \sporkTid`: is `\sporkTid` the whole set of thread IDs (Conventions says an unsubscripted capital is the set)?
  If so, it should depend on `clusterDim`/`warp_config`, because "all threads" means all threads of this launch.

## Possible refinements

- [ ] E-LogicLhs/Rhs evaluate both operands, so there is no short-circuiting.
  Because reading annotated windows emits trace events, short-circuit versus strict evaluation is observable in `\sporktr^*`.
  Whichever we choose, the doc should state it.
- [ ] `#` means two things: the window annotation (`\sporkw \# \sporkwinAnn`) and the configuration separator (`\sporksigma \# \sporktr^*`).
  The new syntax puts both inside one `\langle\ldots\rangle` (e.g. W-KeepAnnotation), which reads ambiguously.
  Consider a different separator for the σ/tr pair, such as `;` or `\mid`.
- [ ] Expression rules never change `\sporksigma`, and many only thread `\sporktr^*` through a congruence.
  A shorthand for "this rule is a pure congruence over the trace" could shrink figures further.
  The trade-off is that the explicit `\sporkSub{\sporktr^*_1}{\sporktr^*_2}` makes the trace effect visible, which is the main point of the syntax.
- [ ] In the ExprSemantics caption, the constant-folding examples are now written as premise-less `\sporkRule` axioms with no fraction bar.
  The old form had an empty-premise fraction, which renders badly with the boxes at caption size.
  Check that this matches how you want axioms written elsewhere.
- [x] Prefix operators outside a `\sporkSub` are easy to misread. (David changed `\sporkSub` so one outer box wraps both sides; colors may be tweaked later.)
  In E-Negate, `-\sporkSub{\sporke_1}{\sporke_2}` correctly means `-e_1` before and `-e_2` after.
  But the `-` renders right next to the LHS box only, so it looks like the minus was dropped from `e_2`; David hit this on first reading.
  Possible fixes: a thin space or a bracket that visibly wraps the whole box pair, or a sentence in Semantics.tex with a prefix-operator example.
  Postfix context (W-Lo's `\sporkSub{e_1}{e_2}\texttt{:}e`) has the mirror-image problem.
- [ ] Axioms that rewrite a whole term (C-SeqDone, C-If*, C-For*, C-CudaDeviceFunction) end up with one big `\sporkSub` around the entire statement.
  That is correct but long; C-ForIter is the widest rule in the figure.
  A tighter option is to substitute only the parts that change, e.g. C-SeqDone as `\sporkSub{\texttt{pass;}}{\epsilon}\sporks`, or C-ForIter as `\sporkSub{\epsilon}{\sporks'\texttt{;}}\texttt{for...(}\sporkSub{z_lo}{z_lo+1}\texttt{,...}`.
  But empty-side substitutions are harder to read and stretch the "syntactic substitution" convention.
  I used whole-term subs for now.
- [ ] The scalar-read restriction (`\sporkwH` in `\sporke` must contain only point coordinates) appears only in prose ("expects scalar").
  It could be enforced syntactically, e.g. with a `\sporkwz`-like point-only nonterminal.
- [ ] Substitution never happens inside subscripts. For example, `\sporktr^*_1` is a metavariable name, not `\sporktr^*` with `_1` substituted into it.
  This is implicitly true today but not stated in Semantics.tex.
  It may matter for future repetition/clarity tradeoffs (David's note).
