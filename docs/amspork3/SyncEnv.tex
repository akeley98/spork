\sporkSection{Synchronization Environment}{sec:SyncEnv}

The goal of the synchronization environment is to ``compress'' the trace into an environment-like object that records a summary of the prior reads and mutates done to each array element.
Rather than keeping the literal trace, the prior reads and mutates are summarized based on analyzing how synchronization events propagate the observation of the read or mutate to more threads.
Define
\begin{align}
    % Already defined EnvEff, but this is the proper place.
    \sporkenvEff: \sporkEnvEff &\Coloneqq (\sporkmut, \sporkx, \sporkz_i^*) \\
    \sporkenvVis: \sporkEnvVis &\Coloneqq (\sporkOb_v, \sporkAw_v, \sporkQtlMask) \sporkComment{\quad(``visibility record'')}\\
    \sporkEnv &= \mathcal{P}(\sporkEnvEff \times \sporkEnvVis)
\end{align}
Each $(\sporkenvEff, \sporkenvVis)$ pair in a given $\sporkenv:\sporkEnv$ corresponds 1:1 with a $\sporkTrPostAccess$ event
(if we ignore set de-duplication).
The ultimate goal of this section is to define $\sporkenv$ and $\sporkConcatEnv$ as semantics-preserving drop-in replacements for $\sporktr^*$ and $\sporkConcatChk$; i.e., that alternative semantics (Section~\ref{sec:Semantics}) with $\sporktr^*$ and $\sporkConcatChk$ replaced with $\sporkenv$ and $\sporkConcatEnv$ will get stuck on an input program iff said program gets stuck with the original semantics.
For brevity, we allow treating $\sporkenv$ as a relation $\sporkEnvEff \to \mathcal{P}(\sporkEnvVis)$;
this looks up a set of visibility records corresponding to prior $\sporkTrPostAccess$ events matching a certain effect (``read/mutate at $\sporkx[\sporkz_i^*]$'').
\begin{align}
    \sporkenv(\sporkenvEff) = \{ \sporkenvVis \mid (\sporkenvEff, \sporkenvVis) \in \sporkenv \}
\end{align}
