\magicSubsection{Camspork Implementation Details And Deviations}{sec:CamsporkDetails}
% no-VF: camspork receives qual-tl implementation class bitmasks (out-of-order, atomic) when the ProgramEnv/SyncvTable is constructed, and REQUIREs the class rules (no out-of-order qual-tl in precondition sets, no atomic qual-tl in any sync-tl or as initial qual-tl). The out-of-order access flag is gone; the non-convergent optimization (gOooOpt) applies iff the initial qual-tl is out-of-order. Memoization hashing excludes tl-sig intervals holding only atomic qual-tl (sound since atomic qual-tl are never in a first sync-tl).

The implementation deviates from the described semantics:

\begin{itemize}
  \item The free-on-arrive barrier (def~\ref{sec:gFreeOnArriveBarrier}) gets propagated deep into the system, along with status flags associated with managed ring buffers (Section~\ref{sec:ManagedRingBuffers}).
  This is to more eagerly issue ``use before allocate'' and ``use after free'' diagnostics, closer to the actual code that triggered the problem.
  \item The \lighttt{JoinThreads} node (def~\ref{sec:gJoinThreads}).
  \item Out-of-order Non-convergent Abstract Machine Optimization (def~\ref{sec:gOooOpt}).
\end{itemize}
