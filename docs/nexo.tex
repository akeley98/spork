\myBiggerTitle{First-Order Goal}

{\LARGE
What Exo-GPU ideas are nice?

\begin{itemize}
  \item Big assumption: \myKeyA{internal determinism} is acceptable\footnote{escape hatch: atomic re-ordering is acceptable. Could add more escape hatches?}
  \item Break correctness into two orthogonal questions
  \item \myKeyA{Value Correctness:} if we serialize all parallel loops \& async instrs, will the program compute the right value?
  \begin{itemize}
    \item Checked by chain of verified rewrites from original program
    \item Hoping to replace this with something else
  \end{itemize}
  \item \myKeyA{Sync Correctness:} is the synchronization of the real parallel program sufficient to guarantee as-if serialized results?
  \begin{itemize}
    \item Checked by abstract machine sync check
  \end{itemize}
\end{itemize}

}

\newpage
\myBiggerTitle{First-Order Goal}

{\LARGE
In support of this, Exo-GPU has
\begin{itemize}
  \item Language-level reasoning of \myKeyA{parallel loop nests}
  (each stmt statically known to be executed by thread/warp/warpgroup etc.)
  \item Careful cataloging of \myKeyA{hardware instruction} attributes
  \begin{itemize}
    \item Value semantics. In Exo, this is imperative code in \texttt{behavior()}, checked by \texttt{replace()}.
    \item Expected memory type (RMEM, SMEM, GMEM, CPU etc.)
    \item Expected collective unit (thread, warp, etc.) of execution
    \item Expected strides
    \item Sync semantics (qualitative timeline, out-of-order)
  \end{itemize}
\end{itemize}
These concepts will be \myKeyA{very useful} for a new PL

}
